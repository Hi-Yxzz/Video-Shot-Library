# Video Shotcraft 镜头库视觉改版设计

日期：2026-07-27

## 背景

当前镜头库能够搜索、筛选、悬停播放并查看详情，但页面的信息层级更像说明文档：

- 首屏标题和统计数字占用过多纵向空间；
- 宽屏卡片最小宽度只有 280px，视频预览偏小；
- 卡片正文固定约 176px，三行摘要与多组元数据压过预览画面；
- 多变体数字切换条进一步增加卡片高度；
- 详情使用最大宽度 1120px 的弹窗，长摘要先于视频和核心参数；
- 奶油色、琥珀色与棕色层级会影响用户判断镜头自身颜色。

本次设计把产品目标明确为“快速扫片选镜头”，让用户先看画面，再决定是否阅读配方。

## 设计依据

方案采用电影接触表式目录，并吸收以下模式：

- 用户提供的 SHOT//LIBRARY 参考站：大比例预览、吸顶筛选、封面优先、
  悬停播放和独立详情路由；
- ShotDeck：画面优先、高密度检索和多维标签；
- Keyframe Gallery：产品动效的轻文案画廊；
- FrameRate 与 Eyecandy：视频收藏、技术分类和独立内容页。

不直接复制参考站的品牌、数据结构或具体视觉资产。

## 目标

1. 让 1440px 桌面首屏看到搜索筛选和第一排完整镜头；
2. 让 1600px 桌面稳定显示四列大尺寸 16:9 预览；
3. 把卡片中视频与文字的面积比例调整到约 75% : 25%；
4. 把详情播放器放大到当前约 1.5–2 倍；
5. 首页不因 159 条预览而同时下载 159 个 MP4；
6. 保留搜索、分类、多变体、配方、Demo 和复制镜头 ID 的现有能力；
7. 搜索、分类、滚动位置和键盘操作在列表与详情间连续。

## 非目标

- 不增加登录、收藏、项目、分享或协作功能；
- 不修改镜头配方、Remotion 实现或视频内容；
- 不增加新的镜头来源或重新设计镜头分类；
- 不为首页额外生成 WebM 轻量循环视频；
- 不在本设计阶段部署网站；
- 不删除 `letterspace-materialize` 和 `text-as-mask` 之外的镜头。

## 设计方向

采用“电影接触表式镜头库”：

- 中性黑灰界面承托不同色彩的视频；
- 亮橙只表示选中、播放、焦点和主操作；
- 首页使用大预览、短文案和紧凑筛选；
- 卡片悬停承担快速预览，独立详情页承担阅读；
- 不使用左侧栏和详情弹窗。

## 信息架构

### 首页 `/`

从上到下分为：

1. 56px 吸顶导航；
2. 120–150px 紧凑介绍区；
3. 52–64px 吸顶搜索筛选工具栏；
4. 响应式镜头网格；
5. 简短版权与来源说明。

### 详情页 `/shots/[id]`

独立路由展示：

1. 返回目录、上一镜和下一镜；
2. 大尺寸播放器；
3. 多变体缩略图；
4. 镜头 ID、摘要、用途、时长、能量和实现状态；
5. 复制 ID、打开配方和 Demo 文件；
6. 首屏下方的完整技术信息；
7. 四个同分类镜头。

未知或已排除的 ID 显示明确的“镜头不存在”状态，并提供返回目录操作。

## 首页设计

### 导航

- 高度 56px，桌面端吸顶；
- 左侧显示 `VIDEO SHOTCRAFT`；
- 中间保留“镜头目录”和“Agent JSON”；
- 右侧显示 `102 SHOTS / 159 PREVIEWS`；
- 不再重复放置巨大品牌标题。

### 介绍区

- 标题使用“快速找到下一镜”；
- 字号 42–48px，最多一行；
- 说明最多一行，不超过 56 个中文字符；
- 可使用低对比度镜头封面带作为背景，但不得推迟目录渲染或抢占点击；
- 介绍区总高度不超过 150px。

### 搜索筛选工具栏

- 桌面端吸顶在导航下方；
- 搜索框占用剩余宽度；
- 分类使用横向胶囊按钮；
- 显示当前匹配数量；
- 提供“紧凑/舒适”两档密度；
- 手机端允许分类横向滚动，不换成侧栏；
- 搜索、分类和密度写入 URL 查询参数，便于刷新与分享。

### 网格

| 视口宽度 | 列数 | 说明 |
|---|---:|---|
| `>= 1500px` | 4 | 默认桌面接触表 |
| `1100–1499px` | 3 | 笔记本与小桌面 |
| `720–1099px` | 2 | 平板横屏 |
| `< 720px` | 1 | 手机 |

内容最大宽度 1680px，桌面间距 14–16px，水平边距随视口在 16–48px 之间变化。

## 镜头卡片

卡片结构只有两个区域：

```text
┌────────────────────────────┐
│        16:9 预览画面        │
│  ▶                   00:06 │
├────────────────────────────┤
│ ai-stream-response         │
│ [交互] AI 响应过程可视化    │
└────────────────────────────┘
```

### 画面

- 固定 16:9；
- 默认显示 WebP 封面；
- 媒体使用 `object-fit: contain`，不裁切内容；
- 左下角显示播放提示，右下角显示时长；
- 右上角最多显示一个 `N VARIANTS` 标签；
- 不在画面上下重复镜头 ID；
- 不显示当前数字样式切换条。

### 文案

- 镜头 ID 为 15–16px，单行截断；
- 第二行由分类标签和一句简短用途组成；
- 用途使用 12–13px，最多一行；
- 卡片文字区域高度控制在 80–100px；
- 长摘要、Demo 状态、文件路径和实现说明只在详情出现。

### 悬停与聚焦

- 鼠标悬停 120ms 后才请求并播放对应本地 MP4；
- 鼠标离开后暂停、释放当前播放状态并恢复封面；
- 键盘聚焦执行同样的预览逻辑；
- 页面同时只允许一条卡片预览播放；
- 离开视口立即暂停；
- `prefers-reduced-motion: reduce` 下不自动播放；
- 点击卡片进入独立详情页；
- 悬停效果只使用边框与轻微明度变化，不缩放视频卡片。

## 详情页

### 桌面布局

内容最大宽度 1680px，主区域采用约 68% : 32% 双栏：

- 左侧为播放器和变体；
- 右侧为吸顶信息栏；
- 详情标题使用镜头 ID，而不是长摘要；
- 播放器宽度可接近 1100px，并受可用视口高度约束；
- 非 16:9 镜头按原比例居中显示，不裁切。

### 信息栏

首屏只展示：

- 分类；
- 镜头 ID；
- 不超过三行的摘要；
- 用途；
- 时长；
- 能量；
- 实现状态；
- 变体数量；
- “复制镜头 ID”主按钮；
- “打开配方”和 Demo 文件次级操作。

技术文件路径和完整说明移动到首屏下方，可使用原生 `<details>` 折叠。

### 多变体

- 变体位于播放器下方；
- 使用带封面的横向缩略图，不使用纯数字按钮；
- 当前变体使用亮橙边框；
- 切换后更新播放器、标题和实现状态；
- 手机端横向滚动，保证单个变体至少露出 80% 宽度。

### 连续浏览

- 支持页面内“上一镜/下一镜”；
- 桌面端支持左右方向键切换；
- 从筛选结果进入详情时，上一镜/下一镜遵循该筛选结果顺序；
- 直接打开详情链接时，退回全部镜头排序；
- 返回首页时恢复查询参数和滚动位置；
- 当前筛选结果 ID 与滚动位置保存到 `sessionStorage`，不上传服务器。

### 移动端

- 单栏排列，播放器在上、信息在下；
- 操作按钮保持至少 44px 点击高度；
- 信息栏不吸顶；
- 变体横向滚动；
- 上一镜/下一镜固定在普通文档流，不遮挡播放器控制条。

## 视觉系统

### 色彩

| 角色 | 色值 |
|---|---|
| 页面背景 | `#07080A` |
| 卡片背景 | `#101216` |
| 播放器背景 | `#030405` |
| 普通边框 | `#242933` |
| 强边框 | `#353C48` |
| 主文字 | `#F4F6F8` |
| 次要文字 | `#8B939F` |
| 强调色 | `#FF5A1F` |
| 错误色 | `#FF6B5F` |

删除现有奶油色、琥珀色、橙棕色层级。视频画面之外不得大面积使用强调色。

### 字体与字号

- UI 主字体继续使用系统无衬线字体栈；
- ID、数量、时长和标签使用等宽字体；
- 首页标题 42–48px；
- 卡片 ID 15–16px；
- 卡片说明 12–13px；
- 标签 10–11px；
- 详情标题 32–40px；
- 详情正文 14–16px。

### 形状与层级

- 普通圆角 6px，卡片和播放器最大 8px；
- 主要依靠 1px 边框区分层级；
- 不使用大面积投影、霓虹光晕或渐变背景；
- 焦点环使用 2px 亮橙并保留足够偏移；
- 动效持续时间控制在 120–220ms。

## 媒体与数据设计

### 本地媒体

现有 159 个本地 MP4 继续保存在：

```text
public/media/<style-key>.mp4
```

索引构建时把可用视频的 `previewUrl` 映射为：

```text
/media/<style-key>.mp4
```

上游远程 URL 保留为来源字段，但不用于前端正常预览。缺少本地文件时构建失败，
而不是静默退回远程视频。

### WebP 封面

新增封面目录：

```text
public/posters/<style-key>.webp
```

使用本机已验证的 FFmpeg 8.1 与 ffprobe 8.1 生成：

- 输出画布 640×360；
- 保持原比例并使用播放器背景色补边；
- 默认取视频约 25% 位置的非首帧，避免常见黑场开头；
- 输出路径和视频文件名一一对应；
- 已存在且源视频未变化时跳过；
- 生成后检查图片存在、尺寸正确且非空。

`public/data/library.json` 为每个样式输出 `posterUrl`。卡片先加载封面，只有悬停
或聚焦后才设置 `<video src>`。

### 数据流

```text
upstream-library.json
        +
excluded-shots.json
        +
public/media/*.mp4
        +
public/posters/*.webp
        ↓
build-library-data.mjs
        ↓
public/data/library.json
        ↓
首页筛选 / 卡片预览 / 详情页
```

生成器继续作为镜头数量、排除列表、媒体文件和封面文件的一致性入口。

## 组件边界

### 现有组件调整

- `ShotLibrary`：目录数据、URL 筛选状态和当前播放卡片；
- `ShotCard`：封面、悬停预览和紧凑元数据；
- `ShotVideo`：封面、延迟加载、播放互斥和错误状态；
- `library-model`：筛选、查询参数和详情顺序；
- `globals.css`：新视觉令牌、网格和响应式布局。

### 新增组件

- 详情路由 `app/shots/[id]/page.tsx`；
- `ShotDetail`：详情数据读取和不存在状态；
- `VariantStrip`：带封面的变体切换；
- 封面生成脚本 `scripts/build-video-posters.mjs`。

详情路由稳定后删除 `ShotDialog`，避免同时维护两套详情体验。

## 错误与空状态

- 索引加载失败：保留紧凑页面骨架，显示重试按钮；
- 封面失败：显示中性播放器底和镜头 ID，不显示破图图标；
- 悬停视频失败：保留封面并显示“预览加载失败”；
- 详情视频失败：保留封面、错误摘要和重试按钮；
- 未知镜头 ID：显示“镜头不存在”与返回目录按钮；
- 搜索无结果：保留筛选工具栏，提供清空筛选；
- 本地媒体或封面缺失：构建阶段失败并列出精确镜头 ID。

错误状态不得无限转圈，也不得自动请求第三方远程媒体。

## 可访问性

- 所有卡片、分类、变体和操作均可通过键盘到达；
- 卡片焦点可触发预览，但减少动态效果模式下保持静态；
- 视频提供准确的镜头与变体 `aria-label`；
- 亮橙不作为唯一状态信号，同时配合边框、文字或图标；
- 主文字、次要文字与背景满足正常文本对比要求；
- `<video controls>` 仅用于详情，首页不显示浏览器控制条；
- 关闭自动播放后仍能通过进入详情播放视频。

## 性能预算

- 首页首屏不设置任何卡片 MP4 的 `src`；
- 首屏只加载可见卡片封面，其余封面使用原生懒加载；
- 单张 640×360 WebP 目标大小不超过 100KB；
- 同时播放卡片数严格为 1；
- 悬停取消时终止尚未开始的延迟请求；
- 详情页只加载当前变体原始 MP4；
- 页面不引入新的动画框架或远程字体依赖。

## 测试

### 数据测试

- 排除列表仍只排除已配置镜头；
- 输出严格为 102 张卡片和 159 个预览；
- 每个有预览的样式都有安全的 `/media/` 与 `/posters/` 路径；
- 每个本地媒体与封面文件都存在；
- 不允许目录穿越、远程预览回退和重复媒体文件名；
- 封面生成可重复执行且不产生临时残留。

### 模型与交互测试

- 搜索、分类与密度查询参数可解析和序列化；
- 搜索与分类组合后顺序稳定；
- 上一镜/下一镜遵循当前筛选结果；
- 未知 ID 返回不存在状态；
- 多变体默认值和切换状态正确；
- 减少动态效果模式不会触发自动播放。

### 渲染与构建测试

- 首页服务端骨架包含紧凑导航、介绍区和筛选工具栏；
- 详情路由可以构建和渲染；
- 旧详情弹窗不再出现在产物中；
- 完整 `npm test` 通过；
- Cloudflare Wrangler dry-run 可以包含封面和本地 MP4 静态资源。

### 视觉验收

- 1600px：四列；
- 1440px：首屏看到第一排完整卡片；
- 1200px：三列；
- 768px：两列；
- 390px：一列；
- 卡片正文不超过两行；
- 详情播放器桌面宽度接近 1100px；
- 长中文、长镜头 ID 和多变体均不溢出；
- 首页滚动、筛选、返回和键盘连续浏览无明显跳动。

## 完成标准

满足以下条件后本轮视觉改版完成：

1. 首页与已确认概念图方向一致；
2. 102 张镜头均可搜索和筛选；
3. 159 张封面全部生成并校验；
4. 159 条本地 MP4 可在悬停或详情按需播放；
5. 详情改为独立大画幅页面；
6. 列表与详情状态可以恢复；
7. 自动测试、完整构建、响应式视觉检查和 Wrangler dry-run 全部通过。
