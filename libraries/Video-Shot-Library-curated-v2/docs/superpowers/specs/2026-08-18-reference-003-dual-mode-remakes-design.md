# Reference 003 双模式镜头复刻设计

## 目标

从 `/Users/admin/Desktop/视频/待镜头复刻/3.mp4` 提炼 12 个高质量、可复用的 16:9 知识口播与信息可视化镜头，并生成：

- 9 个 B-roll 的 Fast 与 Fidelity 双版本，共 18 支。
- 3 个 A-roll/人物结构的 Fidelity 版本，共 3 支。
- 合计 21 支 1920×1080、30fps、无声 H.264 MP4。

所有示例文案、数据、品牌和人物身份均替换为可复用的通用内容，不复制原视频的具体叙事信息。

## 模式定义

### Fast

- 仅用于 B-roll。
- 延续现有快速版设计语言：深色基底、高对比强调色、清晰信息层级、短促动画与有限景深。
- 复用参考镜头的信息结构和节奏，不要求逐帧匹配原片颜色与材质。
- 目标是低成本、高复用、容易改文案和数据。

### Fidelity

- 用于全部 9 个 B-roll 和 3 个 A-roll/人物结构。
- 逐帧分析并复刻参考镜头的构图、字体气质、颜色、纹理、图形入场、镜头推拉、视差、景深和遮挡关系。
- 保留原镜头的视觉逻辑，但使用通用文案、通用数据和无特定身份的人物表达。
- A-roll 人物只从 `/Users/admin/Desktop/视频/通用/A-roll` 选取，不直接使用参考视频中的讲述者。

## 首轮验收范围

先完成以下 4 个 B-roll 的 Fast 与 Fidelity，共 8 支预览：

1. B02 黑底观点句排版。
2. B05 群聊面板逐条入场。
3. B07 硬件调度信息卡。
4. B09 人物档案卡轮播。

用户确认首轮视觉方向后，再制作其余 5 个 B-roll 双版本和 3 个 A-roll Fidelity。

## 代码结构

新增独立命名空间，避免与现有 8 个 Fast 和 8 个 Fidelity 冲突：

```text
src/reference-003/
  catalog.ts
  shared/
  fast/
  fidelity/
  aroll-clips.ts
```

`catalog.ts` 是唯一镜头目录，记录：

- 稳定 `shotKey`。
- `kind: "b-roll" | "a-roll"`。
- 支持模式。
- 时长、QA 帧和中文名称。
- Composition ID 与输出文件名。

Composition ID 规则：

- B-roll Fast：`FastR03<PascalSlug>`。
- B-roll Fidelity：`FidelityR03<PascalSlug>`。
- A-roll Fidelity：`FidelityR03Aroll<PascalSlug>`。

`Root.tsx` 从目录映射注册 Composition，不为 A-roll 创建 Fast 空壳。

## A-roll 素材策略

- 只复制实际使用的 3 个片段到 `public/assets/reference-003/aroll/`。
- `aroll-clips.ts` 记录原始文件名、SHA-256、裁切起点、帧数、缩放与 `objectFit`。
- 优先使用分屏、侧栏或有限放大；避免把 1280×720 人物素材大幅放大后产生明显软化。
- 所有 `<Video>` 均 `muted`，最终镜头不携带参考音频或素材音频。

## 视觉与内容约束

- 输出比例固定为 16:9，不复刻原视频水印和字幕。
- 字体优先使用本机可稳定渲染的相近中文字体，并在规格中记录回退链。
- 通用示例避免真实品牌、真实人物姓名、真实财务数字和原文长句。
- Fast 与 Fidelity 共享语义内容模型，但拥有独立视觉组件，不能通过简单换色冒充双版本。
- Fidelity 的关键相机、图层和编舞数据必须结构化，便于后续替换文案而不破坏运动。

## 输出与发布

仓库输出：

```text
out/reference-003/fast/mp4/R03-B01-Fast-中文名.mp4
out/reference-003/fidelity/mp4/R03-B01-Fidelity-中文名.mp4
out/reference-003/fidelity/mp4/R03-A01-Fidelity-中文名.mp4
```

预览文件复制到：

`/Users/admin/Desktop/视频/待镜头复刻/复刻镜头预览`

文件名必须显式包含 `R03`、编号和 `Fast` 或 `Fidelity`，不得覆盖现有成片。

首轮只发布预览。用户确认全部镜头后，再创建独立的镜头库导入清单，把成片原子新增到 `/Users/admin/Documents/镜头库.library`；不得复用只适配首批 8 个 Fast 的旧导入脚本。

## 渲染与质量控制

1. 先为每个镜头渲染 5 个 QA 关键帧，核对构图、文字、遮挡、相机和时间映射。
2. Fast 与 Fidelity 最终渲染均使用 Remotion bundled headless shell 和 `--concurrency=1`。
3. 输出参数固定为 H.264、CRF 18、1920×1080、30fps、无声。
4. 每支 MP4 运行 `ffprobe` 核对编码、尺寸、帧率、帧数和时长。
5. 每支 MP4 做完整解码，并对相邻帧突变和九宫格/缩放异常进行检查。
6. 临时渲染、仓库输出和预览副本通过 SHA-256 核对一致性。

批量渲染开始前必须消除 Remotion 4.0.499 与 4.0.500 的版本混用警告；不得带警告进入 21 支成片渲染。

## 测试

- 目录测试：编号、ID、输出名唯一；A-roll 不包含 Fast；B-roll 同时包含两种模式。
- 时间测试：所有 duration 与 QA 帧落在有效范围内。
- A-roll 测试：素材存在、哈希匹配、裁切不超出素材长度。
- 运动测试：关键相机轨迹连续；禁止离散闪烁和变换原点跳变。
- 注册测试：Root 中的 Composition 数量和目录一致。
- 视觉测试：首轮 8 支逐镜头关键帧对照参考帧人工审查。

## 失败处理

- 任一镜头测试、类型检查、关键帧审查或完整解码失败时，不复制到预览目录。
- 渲染中断或发现异常帧时，只重渲受影响镜头，不提高并发重试。
- A-roll 素材不合适时，从通用目录重新选片，不冻结帧或强行拉伸补足时长。
- 参考视频平均帧率元数据不是精确 30fps；参考切点以秒记录，输出统一量化为 30fps，避免累计漂移。
