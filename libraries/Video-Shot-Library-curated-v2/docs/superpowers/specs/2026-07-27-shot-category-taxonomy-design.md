# 镜头标签统一分类设计

## 目标

统一 Video Shotcraft、Remocn 和 Remotion Bits 三个来源的镜头分类。分类依据从“上游实现技术或原始标签”改为“镜头的主要视觉目的”，避免文字动画、数字滚动和整页移动被笼统归入“光效与强调”。

本次只调整分类标签与生成规则，不修改镜头等级、名称、预览方式、源代码或视觉实现。

## 当前问题

导入脚本目前将多个上游类别直接映射到 `effects`：

- Shader 背景
- 动态背景
- 粒子效果
- 视觉效果

未识别的类别也默认回退到 `effects`。这种映射只关注上游技术分类，无法表达镜头的实际观看目的。例如文字逐行滑入、数字滚动、整页推拉和场景切换都可能因上游标为“视觉效果”而进入“光效与强调”。

## 统一分类原则

每个镜头只保留一个主分类，以观众首先感知到的叙事对象和用途为准，而不是以实现所用的 CSS、Shader、粒子或 Remotion 组件为准。

### 分类定义

| 分类 | 判断标准 | 典型内容 |
| --- | --- | --- |
| 开场与品牌 | 建立品牌、片名或开场身份 | Logo、品牌开场、片头 |
| 文字与字卡 | 文字、字符或数字本身是主要表演对象 | 标题、段落、打字、手写、单词替换、数字滚动、计数器 |
| 界面登场与陈列 | 页面、卡片或组件作为内容集合进入并完成布局 | 卡片墙、页面展开、组件批量入场 |
| 运镜与空间 | 摄像机或整个场景的空间位移是主体，内容没有被替换 | 推近、拉远、漂移、环绕、穿越 |
| 数据与指标 | 重点是数据关系、测量结果或指标状态 | 图表、仪表、进度、数据比较 |
| 交互与功能演示 | 用户操作与界面反馈之间的因果是主体 | 点击、拖动、输入、选择、状态切换 |
| 转场 | 旧场景被新场景替换，或页面之间发生交接 | 推页、翻页、遮挡切换、共享轴切换 |
| 节奏与蒙太奇 | 多元素或多镜头按节拍编排，节奏结构高于单个对象 | 硬切串、节拍列表、蒙太奇 |
| 光效与强调 | 光影、粒子、Shader、纹理或装饰性冲击本身是主体 | 辉光、扫光、火花、背景 Shader、环境粒子 |
| 收尾 | 结束、品牌落版或行动号召 | Outro、Logo 收束、CTA |

### 复合镜头优先级

复合镜头按以下顺序判断，避免实现技术覆盖实际用途：

1. 发生场景替换时，优先归“转场”。
2. 有明确操作与反馈因果时，优先归“交互与功能演示”。
3. 文字、字符或数字承担主要信息与运动时，归“文字与字卡”。
4. 页面或组件集合完成入场但没有场景替换时，归“界面登场与陈列”。
5. 整个场景发生空间运动但内容不替换时，归“运镜与空间”。
6. 以图表、测量关系或数据状态为主体时，归“数据与指标”。
7. 只有当光影、粒子、Shader、纹理或装饰性冲击本身是主要视觉目的时，才归“光效与强调”。

数字滚动默认归“文字与字卡”。只有当数字用于表达图表关系、仪表状态或多指标比较时，才归“数据与指标”。

## 数据与代码设计

保留上游类别的基础映射，同时增加按镜头 ID 维护的显式覆盖表：

1. 基础映射处理语义明确的上游类别，例如“文字动效”映射到 `typography`。
2. 覆盖表纠正上游类别过宽或镜头本身属于复合语义的情况。
3. 未识别的上游类别不再静默回退到 `effects`，而是抛出带镜头 ID 和类别名称的错误，要求显式决定。
4. 生成后的 `source/graded-library.json` 和 `public/data/library.json` 继续作为派生产物，由现有脚本统一刷新。

覆盖表只记录例外镜头，不复制名称、描述、等级或评分，避免形成第二份镜头数据源。

## 测试设计

测试先于实现添加，并至少覆盖以下行为：

- 数字滚动、单词替换和逐行文字滑入被归入 `typography`。
- 共享轴、推页和场景交换被归入 `transition`。
- 整页漂移或推近但不换场的镜头被归入 `camera`。
- Shader、粒子和纯光效仍归入 `effects`。
- 未识别的上游类别会明确报错，不会落入“光效与强调”。
- 重新生成的数据与提交文件一致。

## 验收标准

- “光效与强调”中不再出现以文字、数字滚动或整页位移为主要内容的镜头。
- 同一分类规则同时适用于 Remocn 与 Remotion Bits。
- 标签数量和筛选结果由生成数据自动更新。
- 所有现有测试与新增分类测试通过。
- 本地预览中抽查“文字与字卡”“运镜与空间”“转场”“光效与强调”四类，分类符合主要视觉目的。
