# “AI 味”视频三镜头复刻验证设计

## 目标

基于第 20 期视频《为什么 AI 做的界面，总有一股 AI 味？》的现有文案和素材，复用三个已完成的 Remotion 镜头系统，制作三段无声、独立、可审阅的 1920×1080 预览视频。

本次验证关注模板在新语义、新素材和新视觉体系中的复用效果，不制作完整成片，不进行配音或字幕时间轴同步，也不覆盖已有模板或历史导出文件。

## 输入

内容项目：

`/Users/admin/Desktop/视频/20-为什么AI做的界面，总有一股AI味？`

使用以下现有内容：

- 口播稿：`文案/AI为什么总做出一股AI味？｜3分40秒口播稿.md`
- VOX 人物：困惑理发师、模糊要求顾客
- UI 五风格：默认 AI 味、Swiss、Glassmorphism、Neubrutalism、Aurora
- 原生图形：五项提示公式及相关视觉参考

模板来源：

1. `Fidelity406158StagedTrainingQuestion`，195 帧，6.5 秒
2. `FidelityCaseCardConstellation`，180 帧，6 秒
3. `FidelityR03TeamRelationshipGraph`，309 帧，10.3 秒

前两个模板位于当前 Remotion 工程。第三个模板目前位于 `feature/reference-003-first-batch` worktree，实施时只迁移该镜头运行所需的最小源码与运动数据，不合并整个功能分支。

## 总体结构

新增独立命名空间 `src/ai-flavor-validation/`，避免直接改写三个历史模板。新 Composition 复用原模板的时间结构、镜头运动和关键视觉编排，但拥有独立的文案与素材映射。

计划注册三个 Composition：

| Composition ID | 内容 | 帧数 |
|---|---|---:|
| `AiFlavorBarberAmbiguity` | “剪帅一点”的模糊指令比喻 | 195 |
| `AiFlavorStyleConstellation` | 同一页面的五种视觉风格 | 180 |
| `AiFlavorPromptFormulaGraph` | 可执行界面需求的五项公式 | 309 |

所有 Composition 统一使用 1920×1080、30fps、无音频。

素材复制到 Remotion 工程的 `public/ai-flavor-validation/` 下，通过 `staticFile()` 引用。复制件仅服务本次验证，不修改第 20 期素材源文件。

## 镜头一：模糊指令比喻

### 内容

复用“问题起点与阶段训练”的 Fidelity 运动结构。

- 起始指令：`给我剪帅一点`
- 主要人物：困惑理发师与模糊要求顾客
- 阶段问题：`短一点？`、`长一点？`、`商务一点？`、`潮一点？`
- 最终巨幅问题：`什么叫帅？`
- 辅助结论：`感觉，不是具体指令`

### 编排

保持原模板的纸张层级、档案卡入场、阶段标签、前景遮挡、景深与最终加速推进。人物素材替代原有通用人物表现，但不改变关键镜头边界。

前半段建立“模糊要求”，中段将四种可能解释逐层展开，后半段收束到最终问题。最终问题必须在缩略图和移动端预览尺寸下清晰可读。

## 镜头二：五风格案例星座

### 内容

复用“案例卡片星座”的 Fidelity 运动结构。

- 中心节点：`同一个 MeetFlow 页面`
- 五张案例卡：`默认 AI 味`、`Swiss`、`Glassmorphism`、`Neubrutalism`、`Aurora`
- 总结文案：`功能、文案、结构不变，只换风格词`

### 编排

五张卡片使用各风格的 `hero-1920x1080.png`，以统一裁切比例放入卡片。保持分组弹入、中心汇总、连接线延迟绘制和整体轻微拉远。

卡片标签需在静止审阅帧可辨识；UI 截图优先表现整体色彩和布局差异，不要求在卡片尺寸下阅读页面正文。

## 镜头三：可执行需求关系图

### 内容

复用“团队关系图展开”的 Fidelity 运动结构。

- 中心节点：`可执行的界面需求`
- 五个一级节点：`场景`、`结构`、`风格`、`视觉约束`、`禁止项`
- 节点辅助说明：
  - 场景：`这是干嘛的`
  - 结构：`页面怎么排`
  - 风格：`想要什么气质`
  - 视觉约束：`色彩、圆角、密度`
  - 禁止项：`明确不要什么`
- 最终总结：`把感觉翻译成规则`

### 编排

保留原模板的中心节点建立、关系线绘制、外围节点分阶段出现、多平面景深和连续镜头推进。人物关系语义替换为“需求要素关系”，避免沿用团队成员头像或人物标签。

五个一级节点的权重保持一致，最终总结在关系网建立完成后出现，不额外增加第六个并列节点。

## 视觉规则

- 保留模板的构图、运动节奏、层次与 Fidelity 质感，这是本次验证的核心。
- 内容层统一适配第 20 期的 Light VOX 视觉语言：米白底、近黑文字、暖橙强调色，并允许 UI 截图保留各自风格色彩。
- 不把三个镜头简单换成完全一致的静态版式；模板原有的动态辨识度必须保留。
- 不使用真实品牌、真实用户数据或新增生成式人物。
- 中文标题使用项目已有中文字体方案，避免运行时依赖新的网络字体请求。

## 代码边界

- 历史模板继续保留原状，新增适配组件承担本期内容。
- 可抽取无业务含义的运动采样函数或视觉基础组件，但不进行与本次验证无关的重构。
- 第三个模板从 worktree 迁移时，只带入其组件直接依赖；若依赖共享模块，则复制最小函数或在新命名空间内建立等价适配层。
- 所有 `interpolate()` 明确设置边界钳制，避免首尾帧外推造成跳变。
- 素材路径集中定义，缺少素材时应在开发阶段立即报出明确路径，而不是静默显示空白卡片。

## 验证

### 自动检查

- 运行相关单元测试，覆盖三个 Composition 的注册、尺寸、帧率和帧数。
- 运行 TypeScript 类型检查。
- 列出 Remotion compositions，确认三个 ID 均可发现。
- 验证复制素材全部存在且可读取。

### 视觉检查

每段至少渲染五个 QA 帧：建立、入场、中段、完成、末帧。

重点检查：

- 镜头一的人物不被档案卡遮住，最终问题没有溢出。
- 镜头二的五张 UI 卡片裁切一致，连接线落在正确卡片锚点。
- 镜头三的五个节点不重叠，连线不穿过主标题，最终推进不露出画布边缘。
- 三段均无首尾跳帧、字体回退、透明素材黑边和缩放模糊。

完成静帧审阅后，再以 H.264、CRF 18、静音、`--concurrency=1` 渲染最终 MP4。

## 完成标准

- 三段预览与确认的文案映射一致。
- 三段时长分别保持 6.5 秒、6 秒和 10.3 秒。
- 原始模板和原始导出文件未被覆盖。
- 新内容在缩略预览和 1920×1080 全尺寸下均清晰可读。
- 工程类型检查、相关测试和 Composition 枚举通过。
- 三个最终 MP4 同时存在于工程输出目录和第 20 期视频的 `镜头预览` 目录。
