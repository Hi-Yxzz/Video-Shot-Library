# 镜头中文标题与二级标签设计

## 目标

为全部镜头增加可维护的中文展示标题和二级多选标签，并用二级标签筛选替换现有“来源”筛选。镜头的原始 ID、源码路径、来源和许可证保持不变，继续用于复制、检索和 Remotion 调用。

本次同时扩大卡片的详情触发区域，使鼠标、触摸和键盘用户都能从整张卡片进入现有详情弹窗。

## 数据模型

新增本地元数据文件 `source/shot-metadata.json`，以最终镜头 ID 为键：

```json
{
  "remocn/hand-count": {
    "titleZh": "手写数字计数",
    "tags": ["数字", "计数器", "手写"]
  }
}
```

每条元数据包含：

- `titleZh`：非空中文展示标题。
- `tags`：至少一个、无重复的中文二级标签。

最终生成的每张卡片增加 `tags` 字段，现有 `title` 字段改为中文展示标题。`id`、`upstreamId` 和 `compositionId` 不改变。

元数据表是中文标题和二级标签的唯一数据源。页面组件不维护镜头 ID 到标题或标签的映射。

## 元数据完整性

生成目录时执行严格校验：

- 目录中的每个镜头都必须存在元数据。
- 元数据不能包含目录中不存在的镜头 ID。
- `titleZh` 必须包含至少一个中文字符。
- `tags` 必须是非空字符串数组，去除首尾空白后不得重复。
- 标签必须属于允许的二级标签词表。

任何不完整或未知数据都使生成命令失败，并在错误中显示镜头 ID。

## 二级标签体系

二级标签描述镜头的主要对象、表现方式或用途，允许一个镜头同时拥有多个标签。

文字与字卡类至少包含：

- 标题
- 段落
- 单词
- 字符
- 数字
- 计数器
- 打字
- 手写
- 字幕
- 高亮
- 替换
- 滚动

其他一级分类使用同一元数据机制，例如“推近、环绕、翻页、遮挡、粒子、辉光、图表、光标、卡片墙”等。标签词表集中定义，避免同义词分裂，例如不同时使用“计数”和“数字计数”。

## 筛选交互

移除结果区顶部的“来源”筛选组，来源信息继续保留在详情弹窗内。

原位置显示“标签”多选组：

- 标签根据当前一级分类和等级筛选后的可用镜头动态计算。
- 当前一级分类为“全部镜头”时，展示整个目录的可用标签。
- 点击标签切换选中状态，可以同时选择多个。
- 多个标签采用 OR 逻辑：镜头命中任意一个已选标签即可显示。
- 改变一级分类时，自动移除在新分类中不可用的已选标签。
- “清空筛选”同时清空搜索词、一级分类、等级和二级标签。
- 来源不再是筛选条件，但搜索仍可匹配来源名称。

结果数量、空状态和分类计数沿用现有逻辑；二级标签按钮显示各自可匹配的镜头数量。

## 标题与镜头 ID

卡片主标题显示中文标题，原始镜头 ID 在主标题下方以较弱层级显示。详情弹窗顶部同样先显示中文标题，并单独显示原始镜头 ID。

搜索字段同时匹配：

- 中文标题
- 原始镜头 ID
- 中文说明和用途
- 二级标签
- 来源名称
- 样式名称

“复制镜头 ID”继续复制原始 `card.id`，Remotion Player 的 `compositionId` 不改变。

## 整卡进入详情

卡片根元素成为可交互区域：

- 鼠标或触摸点击卡片任意非独立交互区域时打开详情弹窗。
- 键盘聚焦卡片后，按 Enter 或 Space 打开详情。
- 卡片具有清晰的焦点样式和中文无障碍名称。
- 网格预览不显示控制条，因此点击预览区域也打开详情。
- 详情弹窗内的样式切换、复制和外链继续独立工作，不受整卡点击影响。

现有详情仍使用弹窗，不新增独立 URL 路由。

## 测试

测试先于实现，覆盖：

- 元数据完整性、未知 ID、中文标题和标签词表校验。
- 生成后的 276 张卡片全部具有中文标题和至少一个标签。
- 多标签 OR 筛选及与搜索、一级分类、等级的组合。
- 可用标签与标签计数计算。
- 搜索能够匹配中文标题与标签。
- 来源筛选从模型和界面中移除。
- 卡片根元素可点击，并支持 Enter 和 Space 打开详情。
- 卡片和详情中的中文标题与原始 ID 同时存在。

## 验收标准

- 网站不再显示“来源”筛选组。
- 选择“文字与字卡”后可看到标题、段落、数字、手写等二级标签。
- 二级标签支持多选，结果符合 OR 逻辑。
- 每张卡片主标题为中文，原始镜头 ID 保持可见且可复制。
- 点击卡片的预览、标题或空白区域都能进入详情。
- 276 张卡片的数据完整性检查、全量测试和生产构建通过。
