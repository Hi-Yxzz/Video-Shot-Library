# 知识口播精选镜头库 v2 设计

## 1. 背景与目标

现有 `Video-Shot-Library` 已具备镜头配方、Remotion 示例、Shot Runtime、Gallery 和构建脚本，但镜头数量、来源与完成度混杂，难以保证用户选中的镜头都具有稳定的成片质量。

本项目在现有仓库内新增独立的 `curated-v2` 精选层。旧库继续作为素材池和兼容层，不直接重写或删除。精选层面向 16:9 知识口播与信息可视化视频，以 B-roll 为主要内容，同时收录能有效承载信息的 A-roll 构图与转场。

核心目标：

- 从用户提供的完整高质量参考视频中筛选值得复用的镜头语言。
- 对入选片段逐帧分析排版、字体、图形运动、摄影机、视差和背景纹理。
- 将分析结果重构为原创、可参数化、可测试的 Remotion 镜头家族。
- 以固定质量门槛控制收录，不以堆积数量为目标。
- 让每个精品镜头承担明确的知识叙事职责，并能直接组合进横屏口播视频。

## 2. 范围

### 2.1 首期交付

首个可用版本收录 36–50 个精品镜头家族：

- B-roll：约 30–40 个，目标占比约 80%，允许随达标片段在 75%–85% 之间浮动。
- A-roll：约 6–10 个，占 20%–25%。
- 达到质量门槛的镜头可以继续增加，不设置总量上限。

`镜头家族` 是统计和运行时调用的基本单位。左右构图、内容密度、入场方向等同一运动语言的差异作为 `variant`，不重复计算为独立家族。

### 2.2 B-roll 类别

- 概念隐喻与抽象解释
- 流程、因果与系统关系
- 数据、图表与数字证据
- 时间线与历史演进
- 文献、引用与案例展示
- 地图、空间与范围表达
- UI、网页与屏幕内容
- 图像蒙太奇与素材编排
- 章节过渡与节奏桥段
- 总结、聚合与观点回收

### 2.3 A-roll 类别

- 人物居中，两侧建立信息层
- 人物偏置，另一侧承载图表或关键词
- 人物前景与背景大字形成景深
- 人物定格、抠像与多层素材组合
- 重点语句局部推近与字幕强化
- A-roll 向 B-roll 的遮罩、擦除或景深转场
- B-roll 回到人物画面的视觉回收

### 2.4 不在首期范围

- 自动下载或批量抓取第三方视频。
- 保存或分发参考视频中的品牌素材、人物素材和版权字体。
- 将按钮微动效、单个图标动画等零散效果作为精品镜头收录。
- 建设在线非线性编辑器或云端渲染服务。
- 为了达到数量指标而降低质量门槛。

## 3. 总体方案

采用“现有仓库 + 独立精选层”的方式：

```text
Video-Shot-Library/
├── library-sources/              # 现有组件与素材池
├── references/                   # 现有镜头配方
├── curated-v2/
│   ├── references/               # 参考视频和候选片段分析
│   ├── recipes/                  # 镜头家族的设计配方
│   ├── shots/                    # 参数化 Remotion 实现
│   ├── sequences/                # 可复用的多镜头组合
│   ├── fixtures/                 # 演示和压力测试数据
│   └── quality/                  # 验收结果与评分
└── gallery/                      # 精选库与 Legacy 的统一入口
```

Gallery 默认优先展示精选镜头，并明确区分 `Curated v2` 与 `Legacy`。旧 ID 和 Shot Runtime 不在首期被破坏性修改。

## 4. 输入与筛选流程

### 4.1 输入方式

首选输入为用户提供的完整 MP4 或 MOV。用户可以附加特别喜欢的时间段、用途或视觉限制，但这些字段不是必填项。

```text
参考视频：完整 MP4 / MOV
特别喜欢：01:24–01:31（可选）
用途：概念解释 / 数据对比 / 时间线等（可选）
限制：不要人物 / 避免特定颜色等（可选）
```

### 4.2 候选片段生成

完整视频按画面切换、构图变化和语义段落生成带时间码的候选片段。候选片段先评分，再决定是否投入逐帧分析。

每项 10 分，总分 50 分：

| 维度 | 判断标准 |
| --- | --- |
| 信息表达 | 是否让抽象知识更容易理解 |
| 视觉完成度 | 排版、构图、动效和纹理是否统一 |
| 镜头语言 | 推拉、视差、节奏是否有明确意图 |
| 可复用性 | 替换文字和素材后能否服务其他主题 |
| 实现价值 | Remotion 复刻成本是否与复用价值匹配 |

入选门槛：总分不低于 38/50，且“信息表达”和“可复用性”均不低于 7 分。低于门槛的片段保留索引和评分，但不进入实现队列。

同一视频不设置截取上限。所有达标候选完成相似度归并后，再形成镜头家族或现有家族的新变体。预计一条高质量视频贡献 6–15 个镜头或变体，实际数量由质量决定。

## 5. 逐帧分析规范

每个入选片段必须形成独立分析档案，至少包括：

- 来源文件、起止时间码、用途分类和候选评分。
- 建立帧、入场帧、信息峰值帧和退场帧。
- 画布比例、安全区、构图网格和视觉中心。
- 字体候选、字重、字号、行距、字距和对齐方式。
- 图形尺寸、位置、层级、遮罩和混合模式。
- 每个元素的起止帧、运动路径、缩放、旋转、透明度和缓动。
- 摄影机推拉、平移、旋转、景深和屏幕冲击。
- 前景、中景、背景的深度、运动倍率、遮挡和视差关系。
- 颗粒、纸张、网格、辉光、暗角、噪声和光影等纹理实现。
- 节拍点、音效触发点与视觉峰值的同步关系。
- 原片内容中需要保留、泛化、替换和舍弃的部分。

字体无法准确识别时，分析档案必须记录候选字体、判断依据、置信度和可授权替代字体，不把推测写成确定事实。

## 6. 版权与原创重构原则

- 参考视频只用于分析排版、运动、节奏、摄影机和空间组织方式。
- 不直接复制或随库分发第三方标志、人物、插画、截图、音乐和版权字体。
- 无法分离的参考素材使用自制几何图形、授权素材或用户素材重建等价表达。
- 过度依赖特定品牌资产的片段只提炼运动规律，不复刻具体画面。
- 分析档案保留来源和时间码，便于追溯灵感来源与复刻边界。

## 7. Remotion 镜头架构

统一制作基准为 1920×1080、30fps。每个镜头家族使用独立目录：

```text
curated-v2/shots/<category>/<shot-id>/
├── Shot.tsx              # 镜头编排入口
├── schema.ts             # 参数类型、默认值和约束
├── layers/               # 文字、图形、背景等图层
├── motion.ts             # 时间点、缓动和运动曲线
├── camera.ts             # 推拉、平移、视差和景深
├── fixtures.ts           # 最短、标准和压力内容
├── analysis.md           # 逐帧分析与重构决策
└── shot.test.ts          # 参数和关键帧测试
```

### 7.1 参数分组

```ts
type CuratedShotProps = {
  content: {
    title: string;
    body?: string;
    items?: Array<{label: string; value?: string}>;
    media?: string[];
  };
  theme: {
    background: string;
    foreground: string;
    accent: string;
    fontFamily: string;
    textureIntensity: number;
  };
  timing: {
    durationInFrames: number;
    entranceFrames: number;
    holdFrames: number;
    exitFrames: number;
  };
  camera: {
    zoom: number;
    panX: number;
    panY: number;
    parallaxStrength: number;
  };
};
```

镜头可以增加专属参数，但必须保留内容、主题、节奏和摄影机四类边界，并通过 schema 校验类型、范围和必填项。

### 7.2 图层模型

1. 背景层：底色、渐变、颗粒、网格和光影。
2. 内容层：标题、图表、时间线、卡片、人物和图片。
3. 空间层：前中后景深度、遮挡和视差。
4. 摄影机层：整体推拉、平移、旋转和冲击反馈。

动画统一由 Remotion 帧时间驱动，禁止依赖渲染时不可重复的随机数或独立 CSS 时间轴。需要随机分布时使用可配置种子。镜头时长变化采用阶段比例与最短可读时间共同约束，不对整段时间轴做无条件线性拉伸。

## 8. 数据流与状态

```text
用户提供完整视频
        ↓
切片索引与候选评分
        ↓
用户确认候选清单
        ↓
逐帧分析与原创重构决策
        ↓
Remotion 动态草模
        ↓
关键帧和低清预览验收
        ↓
精修、参数化与压力测试
        ↓
质量评分
        ↓
Curated v2 注册表与 Gallery
```

候选、分析、实现、验收和发布状态分开记录。未通过质量门槛的镜头不得仅通过修改展示状态进入精选库。

## 9. 错误与降级处理

- 视频无法解码：记录工具错误和文件信息，请求用户提供兼容编码版本，不生成虚假分析。
- 镜头边界不明确：保留带上下文的较长候选，分析阶段再确定精确时间码。
- 字体无法确认或授权：使用记录过置信度的授权替代字体。
- 参考素材无法分离：用可授权素材或程序图形重建，或只保留运动规律。
- 内容超过镜头容量：启用明确的字号、换行、裁剪或分页降级，并在 schema 中暴露容量限制。
- 素材缺失：显示可辨认的占位状态并阻止正式验收，不静默隐藏元素。
- 性能超限：先降低非核心纹理、模糊和粒子密度，保持信息层和镜头运动不变。

## 10. 质量验收

每个镜头依次通过四道门槛：

1. 分析验收：逐帧分析字段完整，重构边界明确。
2. 静态验收：检查建立帧、信息峰值帧和收尾帧的构图、溢出、对比度、遮挡和视觉中心。
3. 动态验收：检查完整视频的卡顿、缓动、信息可读时间、视差、进退场和音画卡点。
4. 泛化验收：使用最短、标准和压力内容渲染，确认镜头不依赖单一演示文案。

质量评分为 100 分：

| 项目 | 分值 |
| --- | ---: |
| 信息清晰度 | 25 |
| 视觉完成度 | 20 |
| 动态节奏 | 20 |
| 空间与镜头感 | 15 |
| 内容适应性 | 15 |
| 性能与稳定性 | 5 |

- 85–100：进入精选库。
- 75–84：返回精修，不得发布为精选镜头。
- 0–74：停止投入或重新设计。

每个镜头至少提供三套 fixture：最短内容、Gallery 标准内容和包含长标题、多项目或极端数值的压力内容。

## 11. 测试策略

- Schema 测试：必填项、默认值、类型、范围和容量限制。
- 确定性测试：相同输入和帧号产生相同布局与动画状态。
- 关键帧测试：建立、峰值和收尾帧能稳定渲染。
- 内容压力测试：长文本、多项目、缺省字段和极端数值。
- 运行时注册测试：精选 ID 唯一，variant 指向有效家族。
- 数据生成测试：Gallery 和 Shot Runtime 获得一致的精选元数据。
- 完整渲染抽检：每个家族至少一个标准 variant 输出 MP4 并人工验收。

## 12. 批次交付物

每批参考视频产出：

- 候选片段时间码与评分表。
- 入选片段逐帧分析报告。
- 原创重构决策与版权边界说明。
- 可编辑 Remotion 镜头源码和 schema。
- 最短、标准和压力三套示例数据。
- 关键帧截图和动态预览视频。
- 质量评分、已知限制和适用场景。
- Curated v2 注册表与 Gallery 数据。

## 13. 成功标准

- 首个版本包含 36–50 个通过 85 分门槛的镜头家族，其中 B-roll 目标占比约 80%，允许在 75%–85% 之间浮动。
- 每个镜头均能追溯到参考片段、逐帧分析和原创重构决策。
- 每个镜头均通过三套内容 fixture、关键帧渲染和动态验收。
- 同一镜头可替换知识主题、文字、数据、图片和主题颜色，不依赖原参考素材。
- Gallery 能清楚区分精选库、镜头家族、variant 与 Legacy。
- 现有 Legacy 数据和 Shot Runtime 的既有 ID 不被破坏。

## 14. 实施顺序

1. 建立精选层目录、元数据 schema、评分格式和 Gallery 状态模型。
2. 选择一条完整参考视频完成端到端试点。
3. 用试点校准逐帧分析格式、参数边界和质量评分。
4. 按视频批次扩充 B-roll 家族，并同步补充少量 A-roll 家族。
5. 达到首期数量和质量目标后，评估是否将 Curated v2 设为 Gallery 默认入口。
